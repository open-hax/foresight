# Decide where the four capabilities live and what depends on what

Repository, Transduction, Evaluation and Representation are already written as
four epics — inside Knoxx, in PR #238, where they narrow existing Knoxx cards
and inherit Knoxx's deployment, auth, policy database and frontend. The working
intent has since changed: these are meant to stand on their own, separately from
Knoxx, so that a client can substitute Optimizely for the repository or their own
vendor for transduction without taking Knoxx with it.

That is a housing decision, and it should be made once, deliberately, before any
of the four gets built somewhere by default.

This card decides. It does not name anything — naming is downstream of knowing
what the thing is.

## What has to be decided

1. **Where the code lives.** A new repository; a package inside Foresight beside
   `alpha/`; or staying in Knoxx behind internal boundaries. Each has a real
   cost and the costs are not symmetric.
2. **What Knoxx becomes.** The epic language in #238 says Knoxx should be "one
   useful open-source implementation". If the capabilities move out, Knoxx is a
   consumer and a provider host — that should be stated, not left implied.
3. **Which direction dependencies point.** The capabilities must not depend on
   Knoxx. Whether they may depend on Katamorph, Alpha, or eta-mu is the actual
   question, and the runtime ladder in root `AGENTS.md` constrains the answer.
4. **What happens to PR #238.** It is open and blocked. Either it lands as the
   record of intent and the capabilities move out afterwards, or it is closed and
   its four epics are rewritten in their new home. Leaving it open indefinitely
   is the outcome to avoid.

## Constraints already established

- The four names are settled. Do not reopen them.
- Repository must be provider-neutral: EDN/files is the reference provider,
  Optimizely is another. Neither is the contract.
- Evaluation must not be built on `TranslationReview`; translation is a consumer.
- Representation is an axis, not a renderer. `uxx-shared-markup-html-helix-renderers`
  is the existing lower-level foundation and stays valid.
- Per root `AGENTS.md`: shapes, laws and pure functions default to `.cljc`;
  runtime coupling stays at the edge. That applies to all four.

## Done when

- One written decision records the housing, the dependency direction, and what
  Knoxx's role becomes, with the reasoning — not just the outcome.
- PR #238 has a disposition: merged, closed, or explicitly parked with a reason.
- The four capability cards in this set carry the decided home, so none of them
  starts by re-litigating it.
