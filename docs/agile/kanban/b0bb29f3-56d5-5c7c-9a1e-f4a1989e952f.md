# Admit one current-head approval from the reviewer set

## Outcome

Invite every installed reviewer while making admission depend on one valid exact-head approval and deterministic proof.

## Scope

- Implement the canonical PR skill gate in riatzukiza/.agents #8; reusable GitHub gate law stays in eta-mu.
- Keep CodeRabbit/Codex provider records distinct from MiMo/Kimi worker verdicts and imported CodeRabbit CLI artifacts.
- Preserve every actual finding and its disposition, regardless of which provider supplied the qualifying approval.
- Change required aggregate contexts only after their policy and fixtures are reviewed. Never remove deterministic gates to compensate for unavailable providers.

## Acceptance

- [ ] Red/green fixtures cover formal GitHub approval and explicit completed passing/no-issues verdicts with verified current-commit coverage from each eligible identity.
- [ ] Zero approvals, stale approval, spoofed author, acknowledgement-only, skipped/rate-limited review, partial coverage and superseding changes-requested cannot qualify.
- [ ] One current approval plus an unavailable optional reviewer can qualify; required CI failure, unresolved finding or partial input still blocks.
- [ ] Manual CodeRabbit requests respect low-star policy, existing pending requests and observed cooldowns.
- [ ] Exact GitHub rules, App identities, CLI evidence contract and adoption status are recorded before activation.
- [ ] The required context enforces its trusted App issuer and independently pinned gate code/configuration. Candidate workflow edits and same-name foreign statuses cannot self-authorize; imported CLI artifacts do not become native approval.
- [ ] Strict up-to-date checks or merge queue bind base SHA and tested merge candidate; a base-change race forces a fresh tested combination.
