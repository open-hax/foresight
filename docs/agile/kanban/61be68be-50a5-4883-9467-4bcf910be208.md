# Own the Repository contract with EDN files as the reference provider

The useful open-source core here is not a visual editor and not a particular
backend. It is a resource repository contract: identity, schema, references,
versioning, read / write / list, and a provider boundary underneath.

The client will use Optimizely. That is fine, and it is the reason the boundary
has to be real rather than aspirational — the EDN/files implementation has to be
*a* provider, not the shape everything else is written against. The EDN provider
earns its place on its own merits: transparent, Git-native, diffable,
scriptable, AI-readable, and fast to develop against.

## Scope

- Portable `.cljc` laws for resource identity, schema binding, cross-namespace
  references, and the repository operations.
- A provider protocol that Optimizely, Git, a database, or a remote API could
  satisfy without any of them being named in the contract.
- The EDN/files provider, reusing the existing namespace/resource EDN shape
  rather than inventing a second document language.
- Canonical id and reference resolution stated once. Knoxx #230 found the real
  version of this bug: manifest entries stamp namespace-local ids that then fail
  a `qualified-keyword?` law, so manifest-sourced resources could not validate at
  all. Whatever this contract says about qualification, it says once, and both
  own-ids and references obey the same rule.

## Non-goals

- Not publication reconciliation or effects.
- Not transduction, evaluation, or representation.
- Not a visual editing UI.
- Not an Optimizely provider yet — but the contract is wrong if writing one later
  would require changing it.

## Done when

- Two providers exist against one contract, and the second one is not EDN. A
  memory-backed provider is enough to prove the boundary; a fake that only tests
  can reach is not enough to prove it is used.
- A consumer reads a resource without knowing which provider served it.
- A namespace-local reference and a fully-qualified reference to the same
  resource compare equal, and conflicting payloads for one canonical id fail
  deterministically rather than by enumeration order.
- Round-tripping a resource through the provider boundary preserves qualified
  identity exactly.
- **Something calls it in production**, not only tests.
