# Route Alpha's laws through the Katamorph registry consistently

Alpha currently speaks two dialects. `alpha.law.markdown.profile` and
`alpha.law.markdown.facet` validate through `katamorph.schema.core`, returning
`{:ok ...}`. `alpha.law.artifact` calls `malli.core/explain` and
`malli.error/humanize` directly, returning `{:valid? ...}`.

Callers therefore have to know which half of Alpha they are talking to in order
to read a result. The root rule is that Katamorph contracts should be reusable
between stages rather than restated by each runtime; restating them between two
namespaces of the same package is the same defect one scope smaller.

Skipping Katamorph in the first slice was a deliberate, correct call — the note
says so — because Katamorph's schema core was CLJS-only at the time. That reason
has now expired.

## Acceptance

- One validation result shape across Alpha. Pick `:ok` or `:valid?` and
  converge; do not translate between them at call sites.
- `alpha.law.artifact` registers its schemas in the Katamorph registry rather
  than holding a private `schemas` map, or the reason it must not is recorded.
- The `alpha/artifact-owns-embedded-relation-source` law and the
  `reaction-operation-registered` law survive the move with their structured
  findings intact.
- Suites still green on every runtime the portability lane covers.
