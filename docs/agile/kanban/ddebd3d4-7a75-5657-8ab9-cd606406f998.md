# Reconcile fork staging and promotion PRs

## Outcome

Turn a qualified personal-fork merge into exact-SHA staging proof and idempotent upstream/Foresight PRs.

## Scope

- Reuse fork-dev-origins and its mapped fork/network identity; preserve protected main history.
- A fork merge submits artifacts to trusted Services orchestration. Candidate code never receives host deployment credentials.
- Successful staging is required before creating/reusing the in-org promotion branch/PR and affected Foresight integration PR.
- Preserve existing Proxx staging-to-main behavior until a separately reviewed migration; production is a separate evidence gate.
- Sync upstream merge history back through a protected fork PR; use immutable receipt-bound commits rather than moving branch tips.

## Acceptance

- [ ] A fixture fork merge deploys its exact SHA to staging and records public readiness and behavior evidence.
- [ ] Failed or absent staging opens neither promotion nor integration PR.
- [ ] Duplicate/out-of-order events reuse jobs and PRs; a delayed old event never substitutes newer fork main.
- [ ] Integration updates only affected, reachable child gitlinks and requalifies its new head.
- [ ] Protected fork sync preserves ancestry and allows the next promotion without force pushes.
