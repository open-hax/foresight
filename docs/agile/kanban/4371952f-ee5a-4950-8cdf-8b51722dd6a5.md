# Give Transduction one outer contract that survives changing modality

Translation is one instance of a general capability. The ML word for the general
one is *transduction* — sequence-transduction literature puts speech
recognition, machine translation and text-to-speech under the same abstraction,
which is exactly the property wanted here: the contract must not assume that
source and target are both text.

```text
en text   → fr text      machine translation
speech    → text         transcription
text      → speech       synthesis
speech    → fr speech    speech translation
image     → text         captioning
```

One outer shape:

```clojure
{:transduction/input      ...
 :transduction/output     ...
 :transduction/kind       ...
 :transduction/provider   ...
 :transduction/provenance ...}
```

A provider advertises what it can do — in terms of source and target shapes
rather than a growing enum:

```clojure
{:transducer/id           :some/provider
 :transducer/accepts      ...
 :transducer/emits        ...}
```

## Scope

- Portable `.cljc` laws for the transduction request, the candidate result, and
  provenance.
- Provider capability advertisement expressed as shapes, so compatibility is a
  schema question the workflow layer can already answer rather than a bespoke
  matcher.
- Machine translation as the first concrete transducer, using the existing
  translation path as the reference implementation.
- Provenance and execution receipts are part of the output, not a side channel.
  A candidate whose provenance is missing is not a valid candidate.

## Non-goals

- Not publication intent, and not long-term resource authority.
- Not human judgment about the candidate — that is Evaluation, and the two must
  not be joined here. The Knoxx card `knoxx-translations-event-sourced` already
  makes the related point that candidate history and review history are
  different things.
- No second modality implemented in this card. The test is whether one *fits*
  without changing the contract, not whether it ships.

## Done when

- The machine-translation path runs through the general contract with no
  translation-specific key in the outer shape.
- A speech-to-text transducer can be described — request, provider
  advertisement, candidate, provenance — with **zero change** to the laws.
  Describing it is the acceptance test; implementing it is not.
- Selecting a provider is a contract decision, not an environment variable.
  Knoxx #233 removed three separate translation-model authorities, one of them a
  dormant per-source override that would have silently won; do not reintroduce
  that shape.
- Model and provider identifiers survive round-tripping exactly. Real catalog ids
  are `"xiaomi/mimo-v2-pro"`, `"gemma4:31b"`, `"gpt-5.5"` — not keyword-safe, and
  Knoxx #233 already paid for assuming otherwise.
- **Something calls it in production**, not only tests.
