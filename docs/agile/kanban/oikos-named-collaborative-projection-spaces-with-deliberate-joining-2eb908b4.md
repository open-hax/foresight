# Oikos: named collaborative projection spaces with deliberate joining

## Context

Planning only for private open-hax/oikos at /home/err/spaces/foresight/oikos. Desktop is a local-first shared workbench. Initial incoming proposal; planning review is not complete. Creation authorizes no implementation, live configuration, deployment, inference, upload or spending.

## Outcome

Share named speculative workspaces without confusing logical membership with physical i3 placement.

## Scope

Many logical memberships reference one physical window. Speculative EDN branches cause no movement. Protect numbered/visible workspaces and output focus. Agent-owned hidden runtime workspaces need admission, scoped leases, conflict-safe revision preconditions and return verification. Human joins through deliberate sidebar acceptance. Sandbox first.

## Non-goals

No native i3 duplicate-window illusion, hidden-workspace security isolation guarantee, autonomous visible-workspace takeover or live movement.

## Acceptance criteria

- [ ] Two projections can reference one physical window; branch editing has zero IPC mutation.
- [ ] Visible/numbered workspaces and output focus are protected; denied admission, stale revisions and expired leases block movement.
- [ ] Human join acceptance and leave/return produce verified observations; failed return is visible rather than reported as restored.

## Verification

Pure CLJC branch/membership tests plus sandbox i3 scenarios for concurrent proposals, focus preservation, lease expiry and unsuccessful return. These are future acceptance checks, not executed implementation evidence.

## Risks

Hidden workspaces are organizational, not isolation; human or external i3 changes may invalidate a return plan.
