# Hold the Pi representation boundary until something needs projecting

Π is product and representation: organize the outcome and express it in some
consumer-facing form. The design decisions are already made and recorded; what
is missing is anything upstream worth representing, which is why this sits in
the icebox rather than the backlog.

Decisions already taken, so they do not get relitigated:

- No second HTML DSL. The existing Helix frontend stays, and React's server
  renderer is the SSR path. Introducing Hiccup alongside it would create two
  subtly different notions of element, props, children, fragment, escaping,
  class names and events.
- The content model is plain Clojure data, not a React element tree and not
  Hiccup. Helix is its projection, not its representation.
- SSR is an execution strategy for an HTML representation, not a capability.
- The contracts and the operation surface are the product boundary; any web UI
  is a replaceable consumer. The client's team writes Angular, which is an
  argument for investing in the semantic kernel rather than finishing a
  bespoke frontend.
- UXX already landed a portable markup AST with separate HTML and Helix
  renderers. That work is not reopened.

## Trigger to leave the icebox

Something upstream produces an artifact that a person actually needs to look at
— most likely the first Mu case, or the board projection from the Clio fold.
Until then this card is a place to keep the decisions from drifting.

## Acceptance

- Π consumes a resolved semantic artifact and knows nothing about where it was
  stored or which operation produced it.
- Representation selection is driven by artifact role, not hardcoded per page.
- The same artifact can reach at least two representations without the kernel
  changing.

---
The strongest available acceptance test for the whole spine is still the one
from the MCP note: an AI walks one SME through one segment from pending to
reviewed receipt to satisfied gate, with no bespoke web component anywhere in
the loop. That test does not need Π at all, which is the point.
